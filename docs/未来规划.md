# DS 娘未来规划与近期产品方向

日期：2026-10-07

本文件保存讨论方向与暂缓的想法，不作为已实现功能清单或动画制作任务。现有版本仍有原生通知 / 桌面伙伴两种模式，纯桌宠模式尚未实现。当前使用与验证以使用说明和验证记录为准。

## 已明确的优先级

先把产品做成可靠、可安装、可日常使用的通知伙伴。动画制作与精修暂缓，继续使用已接入的帧动画，不启动新动作、拆件、骨骼或视频播放器改造。原参考图、认可素材、旧实验与归档完整保留；本轮不修改其他会话的文件或进程。

近期优先解决用户反馈的安装版本 / Dock 图标差异、当前前台会话仍弹气泡、返回全屏后隐藏不正确、锁屏 / 唤醒后连接恢复问题。动作与气泡联合预览属于产品可验证性改进，可复用现有素材；本轮只记录方向，具体功能范围另行确认。

## 纯桌宠陪伴方向

用户已明确：纯桌宠可以在全部已接入动作之间切换，工作、失败、等待、完成都可以作为表演，不限于待机小生活。

目前可复用九个动作：待机、工作、等待、完成、失败、吃大米饭、扔小鲸鱼、摸头开心、摸小鲸鱼。仅使用正式接入且已认可的资源；未通过的实验候选不混入随机播放。

建议按下列规则设计，尚未实施：

- 不依赖 DSH 是否安装 / 连接，不展示“未连接”作为陪伴状态。
- 各动作播放一段后自然切换，默认随机并避免连续重复；可支持固定某个动作。短动作播放完整一轮，持续动作保留适当停留，避免每帧或每秒切换。
- 工作 / 失败只是角色表演，不制造任务失败气泡、真实任务记录或未读计数；角色动作与真实任务状态分开。
- 隐藏 / 睡眠时暂停，恢复后继续陪伴，不补播积压动作；遵循减少动态效果设置。
- 切换回通知伙伴时恢复真实任务表现，保留原有集成配置和未读记录，不把切换模式当作全部已读，不自动卸载插件或修改 DSH。

## 通知模式收敛建议

用户正在考虑取消原生通知；当前建议是把未来的两个用途收敛为“任务通知伙伴 / 纯桌宠陪伴”。此为建议，尚未确认或实施原生通知移除。

| 用途 | 展示 | DSH 关系 |
| --- | --- | --- |
| 任务通知伙伴 | 真实任务动作、气泡、未读会话列表，点击回到对应会话 | 使用现有集成；问题 / 批准仍由用户在 DSH 处理 |
| 纯桌宠陪伴 | 全部现有动作的随机 / 固定表演 | 不接收 DSH 提醒，不产生虚构任务或未读 |

如果确认移除原生通知，则同时取消以 DSH 本体 Dock 角标为当前交付目标：应用以菜单栏提供设置 / 会话入口，不依赖自身 Dock 角标或系统通知权限。通知身份、角标同步、权限管理和模式间重复提醒的复杂度随之减少，但睡眠、断线、会话跳转与前台识别仍需修好。

必须说明的取舍：没有系统通知兜底后，全屏完全隐藏意味着当下看不到任务提醒。建议全屏设置提供“始终显示 / 仅有任务提醒时出现 / 全屏完全隐藏”，任务伙伴默认第二项；隐藏不清未读，可从菜单栏查看。实际全屏显示能力须实机验证，不承诺仅凭现有窗口策略即可实现。

原生通知功能真正移除时，需要明确旧 Native 偏好的迁移、已发送通知的处理、菜单栏与设置入口、两种用途切换和未读保留；不能只删除设置按钮而让旧用户停留在不可访问的模式。既有 PRD / 实现清单保留历史，本轮不把其未完成条目静默删除。

## 暂缓的动画与互动候选

以下全部是未来候选，无排期，不列为已确认开发任务。

| 方向 | 想法 | 恢复制作前的条件 |
| --- | --- | --- |
| 待机丰富度 | 多种眨眼 / 呼吸、从屏幕边缘偷偷探头，随机插入现有小生活 | 先验证现有随机节奏、重复频率、动作衔接与能耗 |
| 拖拽反馈 | 拖起时挣扎或“快放我下来”，放下后恢复 | 拖动、透明命中和提醒优先稳定；新素材单独确认 |
| 轻触互动 | 摸头开心、点击尾巴、小鲸鱼抛接 | 动作可打断、有冷却、不误触、不影响任务跳转；既有害羞候选未通过 |
| 回来打招呼 | 长时间离开或解锁后挥手欢迎 | 唤醒恢复先可靠，再设计低频触发，避免每次切应用都打招呼 |
| 桌面漫游 | 自己来回走、停在边缘探头 | 固定位置可选，用户拖动优先，验证多显示器 / 屏幕边缘和遮挡体验 |
| 音乐起舞 | 先手动跳舞；后续探索随播放器或节拍舞动 | 节拍联动另行核对音频能力、权限与能耗；不默认采集系统音频 |
| 想法重逢 | 从口袋掏出以前记录的想法，每日最多三条 | 先核对重逢接口、算法、数据授权与去重；可关闭、调频，避免连续打断 |
| 形象 / 皮肤 | 暗黑 DS 娘、长腿比例、小尾鳍等内置标识 | 比例先做静态对比；皮肤保持动作兼容，图标区分气泡 / 菜单栏 / App |
| 更多联动 | 便签或冲锋衣结合 | 用户价值和入口明确后再选，不为联动增加独立流程 |
| 跨平台 | Windows 版 | macOS 通知与陪伴体验稳定、用户需求得到验证，再评估独立客户端 |

## 素材与技术路线

当前优先沿用整图帧动画。动画数量增加后，先测量包体、解码内存和实际能耗，再判断是否需要减少空白画布、合并资源或改用透明视频；不能仅因“帧动画素材多”就重做播放器。

Godot 拆件 / 骨骼暂缓，完整工程与诊断留存。若后续视频展示获得用户反馈和画师合作机会，再按稳定角色设计制作一套连续动作，逐动作确认后接入。静态 / 自动检查通过不等于角色视觉通过。
