# DSH Always On V0.1 范围与验收

更新日期：2026-10-08
状态：0.2.0 本地源码实现，双用途与可靠性自动检查通过；真实 DSH / 全屏 / 唤醒验收待完成

## 1. 交付目标

用户安装一个 macOS App，启用内置 DSH 集成后，可以选择任务通知伙伴或纯桌宠陪伴；纯桌宠不要求 DSH。App 能提醒任务完成、失败以及需要用户介入的事件，点击提醒可以回到正确会话。

角色首轮采用简化形象验证事件链路；后续用户已选择 A 均衡 Q 版，当前接入五状态共 20 帧动作与静态回退图。形象实验室长期保留，核心事件与两种模式的验收边界仍独立记录。

核心产品定义见 [PRD.md](PRD.md)。本文件中的“建议”沿用 PRD 的待审阅默认值。

## 4. 开发前可行性验证

以下验证不能用推测代替；调查以实际 DSH 源码或官方资料为依据，记录版本和证据。

| 验证项 | 需要回答的问题 | 对范围的影响 |
| --- | --- | --- |
| 插件体系 | 实际是否支持 TypeScript / Cordis？插件如何加载、注册、卸载？ | 决定 Adapter 与安装器实现 |
| 检测方式 | 有哪些真实配置位置？如何识别版本、多实例或用户自定义路径？ | 决定首次连接流程 |
| 事件能力 | 五类关键提醒能否准确识别？任务结束与工具结束如何区分？ | 决定事件覆盖是否成立 |
| 状态恢复 | 能否查询当前会话状态及尚未处理的等待项？ | 决定重连后恢复能力 |
| 会话定位 | 能否使用稳定 session ID 打开具体会话？何种方式有确认结果？ | 精确跳转属于发布门槛 |
| 查看反馈 | 能否确认前台可见且已加载的目标会话？ | 精确已读边界，源码证据不能替代实测；角标目标取消 |
| 原生窗口 | 置顶、透明点击区域、Spaces、多显示器能否满足产品要求？ | 决定窗口行为与限制说明 |
| 安装分发 | 插件资源打包、签名、公证和最低系统版本如何支持？ | 决定可安装交付物 |

若没有直接跳转 API，可调查受支持的其他精确定位方式。仅打开 DSH 首页不能作为“跳回对应会话”验收通过。

发现关键能力缺失时，先记录限制和替代方案，提交产品范围调整供用户确认，不默默删减必做项。

## 5. 建议开发顺序

### 阶段 A：验证 DSH 能力

明确支持版本、集成注册、关键事件、会话 ID、状态查询和精确跳转方式。将验证结果补回架构与事件文档。

完成条件：关键能力有证据；未解决项明确；没有把候选方案写成已实现能力。

### 阶段 B：建立共享通知链路

实现插件与 App 通信、事件归一化、会话存储、去重、未读与跳转。用任务伙伴的角色 / 气泡验证链路；陪伴动作不进入事件存储。

完成条件：真实 DSH 的关键事件可到达 App；提醒可定位到正确会话；重复事件不会重复提醒。

### 阶段 C：接入简化桌宠

使用五张状态图完成独立窗口、气泡、状态映射、拖动、吸附、位置恢复和置顶设置。素材可以是简化初稿，但必须保持角色一致、状态可辨。

完成条件：两种模式切换顺畅；Pet 具备所有关键提醒与准确跳转能力。

### 阶段 D：恢复与交付

完成多会话、断连 / 睡眠恢复、插件维护、真实 App 安装和分发验证。

完成条件：以下验收场景通过，已知限制有记录，可交付一个安装包。

## 6. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次安装，DSH 存在 | 只下载本 App；启用后确认真实连接；选择模式 |
| 找不到 DSH 或版本不兼容 | 展示明确状态和下一步，不显示虚假的“已连接” |
| 重复启用或注册 | 不生成重复插件、重复配置或重复监听 |
| 纯桌宠随机 / 固定表演 | 九个现有动作；不连续重复，不制造任务 / 未读，离线正常陪伴 |
| 当前前台会话完成 | 默认仅动作，可选动作和气泡 / 静默；失败及待处理默认仍有气泡 |
| 任务伙伴五类提醒 | 对应角色反馈与气泡；不重复发系统任务通知 |
| 工作开始或进度更新 | 显示 working，不因每次工具活动不断弹提醒 |
| 等待事件被查看但未处理 | 未读可清除，waiting 保留；实际处理后才恢复工作状态 |
| 相同事件被重发 | 不产生额外提醒或动画 |
| 旧事件晚于新事件到达 | 不把已恢复的会话错误改回 waiting 等旧状态 |
| 两个会话同时产生提醒 | 列表按未读会话计数；每条提醒跳转目标正确 |
| 角色显示的会话改变 | 已显示气泡的点击目标仍保持原会话 |
| 任务 / 纯桌宠切换 | 立即切换呈现；会话与未读保留；不重播历史提醒 |
| 两种模式的 Dock / 菜单栏 | 伴侣始终不出现在 Dock，菜单栏可打开设置、会话列表及退出；不向 DSH 本体或伴侣写角标 |
| 实际查看与已读 | DSH 前台显示且加载具体会话，或伴侣前台列表显示对应摘要时，清除已确认查看的提醒；后台选中、仅打开设置、关闭气泡和跳转失败不误清 |
| 原 Native 设置迁移 | 转为任务伙伴，未读 / 集成配置保留，不请求权限，撤回本 App 旧通知 |
| 全屏三选项 | 始终显示 / 仅提醒出现 / 完全隐藏；收起后再次隐藏，隐藏未读保留，返回不补弹 |
| 锁屏 / 睡眠恢复 | 多种恢复原因汇合后重建连接，不清未读，旧异步请求不得覆盖新模式 |
| 联合预览 | 九动作与匹配气泡，暂停 / 重播，样例不影响任务或真实期限 |
| DSH 退出 | App 仍运行；Pet 显示未连接，不继续伪装为正在执行 |
| 插件重连 | 使用真实状态恢复；历史快照不引发一批新的完成提醒 |
| App 重启 | 恢复模式、角色位置及未读记录；等待新连接确认实时状态 |
| 跳转失败或会话已删除 | 显示原因和重试/列表入口，不误标为已读或声称跳转成功 |
| 拖动和重启 | 角色吸附屏幕边缘，重启后位置可见且合理 |
| 显示器拔插 | 角色与气泡返回当前屏幕的可见区域 |
| 透明窗口空白区域 | 不妨碍操作下面的应用 |
| 移除集成 | 只删除本 App 管理的插件注册，保留其他配置 |

## 7. 质量与交付要求

- 事件到呈现的建议体验目标为正常本机环境下约 1 秒内，测量环境和结果必须记录；这不是已验证的性能承诺。
- App 空闲时不通过高频轮询持续刷新角色；使用事件驱动和轻量动画。
- 日志记录连接与错误诊断，默认不记录完整对话、代码或敏感内容。
- 用真实 DSH 验证关键事件和跳转；模拟数据不能替代集成验收。
- 重点验证去重、乱序、等待与已读分离、多会话目标绑定、重连恢复。
- 使用实际构建的 App 验证菜单栏、Dock 隐藏、全屏窗口、安装与签名；不能只依据开发预览判断。
- 完成可安装 App / DMG、首次启用说明、已知限制、集成移除说明。
