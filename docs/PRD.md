# DSH Always On 产品需求文档

更新日期：2026-10-08
版本：V0.2 产品收敛
状态：用户确认任务通知伙伴 / 纯桌宠陪伴，本地源码已实现；真实 DSH / 全屏 / 唤醒验收继续记录

## 1. 产品定义

DSH Always On 是一个面向 DeepSeek Harness（简称 DSH）的 macOS 通知 App。用户只安装一个 App，即可选择任务通知伙伴或纯桌宠陪伴；任务用途通过气泡回到对应 DSH 会话，陪伴用途无需 DSH。

App 内置 DSH 集成插件。插件负责感知 DSH 的运行和任务事件，App 负责通知呈现、桌宠窗口、设置和会话跳转。插件属于内部组件，不作为第二个产品分发。

2026-10-08 用户确认收敛为任务通知伙伴与纯桌宠陪伴；取消原生系统通知及 DSH 本体数字角标。桌宠是产品的重要体验；当前采用用户选定的 A 均衡 Q 版与五状态逐帧动作，形象与动作实验室长期保留，后续美术调整继续在同一页面进行。

产品名暂用仓库目录名 DSH Always On，正式名称尚未确定。

## 2. 解决的问题

用户让 DSH 在后台执行任务后，需要及时知道：

- 任务已经完成，可以查看结果。
- 任务失败，需要查看原因。
- Agent 正在等待回答、操作批准或计划审阅。

用户可能同时运行多个会话，因此提醒必须说明来自哪个会话，并能准确跳回。桌宠还提供持续可见的工作状态，让用户不用反复切回 DSH 检查进度。

## 3. 已确认的产品边界

| 项目 | 第一版要求 |
| --- | --- |
| 平台 | Mac-first，SwiftUI / AppKit 原生 App |
| 集成 | 只实现 DSH，结构上保留 Adapter 扩展入口 |
| 分发 | 一个 macOS App，内置插件，用户只安装一次 |
| 产品用途 | 任务通知伙伴 / 纯桌宠陪伴，两种用途在同一 App 内 |

| 角色 | 参考现有图片重新简化，不完全照搬 |

第一版不包含角色聊天、语音、Live2D、骨骼动画、养成、换装、小游戏、角色商店、云端同步、其他 Agent 集成或 Windows / Linux 客户端。

## 4. 两种用途

| 行为 | 任务通知伙伴 | 纯桌宠陪伴 |
| --- | --- | --- |
| 桌宠窗口 | 显示，默认置顶 | 显示，默认置顶 |
| 动作 | 真实任务五状态 + 待机四种小生活 | 全部九动作随机 / 固定表演 |
| 提醒 | 会话气泡、任务列表和精确跳转 | 不接收真实提醒，不生成假未读 |
| DSH | 需要启用集成 | 无需安装 / 连接；保留原集成配置 |
| 入口 | 菜单栏 | 菜单栏 |
| Dock / 系统任务通知 | 均关闭 | 均关闭 |

旧 Native / Pet 偏好迁移到任务通知伙伴；切换不清未读，不卸载插件，不重新播放历史通知。返回任务伙伴时建立新状态基线，纯桌宠期间的事件不补弹。历史 Native / DSH 角标方案保留为已取消记录，见原实现清单。

当前前台完成会话默认只播放动作；失败、提问、批准和计划审阅默认仍有气泡。用户可选择仅动作、动作和气泡或静默；其他会话照常提醒。只有目标会话可见、已加载且收到固定边界查看确认才清未读，提醒形式不决定已读。

全屏提供始终显示、仅有任务提醒时出现、全屏完全隐藏。新用户默认仅有任务提醒时出现；旧全屏开关保留为对应选择。隐藏不清未读，返回桌面不补弹旧队列。没有系统通知兜底；原生全屏 Space、同 Space 视频、最大化和多屏能力需分别记录。

## 5. 首次安装与连接体验

目标流程：下载 DMG → 拖入 Applications → 启动 App → 检测 DSH → 用户启用集成 → App 安装或注册内置插件 → 确认连接 → 选择通知模式。

检测结果需要区分：

1. 没找到 DSH：展示说明，允许重新检测或选择配置位置。
2. 找到可能的配置：显示位置，仍需验证配置和兼容性。
3. 插件尚未启用：引导启用集成。
4. 集成已启用但未连接：说明可能需要启动或重启 DSH。
5. 插件已连接：握手成功，才显示“已连接”。

只发现一个目录不能当作安装成功或连接成功。具体目录、插件注册方式和是否需要重启，必须依据真实 DSH 版本验证。

如果 DSH 不支持程序化注册，允许首次启动中提供明确的一次性启用指引，仍不要求用户另行下载插件。自动集成是目标体验，未验证前不能承诺完全无操作。

不申请系统通知权限，不产生 Dock 角标；旧版已发送的本 App 系统通知在首次新版本启动时撤回。旧 Native / Pet 设置均迁移为任务通知伙伴，保留提醒记录与集成配置。

开机启动建议默认关闭，由用户主动开启。卸载集成时只移除本 App 管理的插件和注册项，保留其他配置。

## 6. 提醒与角色行为

| 事件 | 角色状态 | 气泡示例 | 主动提醒 |
| --- | --- | --- | --- |
| 开始或继续执行 | working | 无需每次弹气泡 | 否 |
| 需要回答问题 | waiting | “有一个问题等你回答” | 是 |
| 需要批准操作 | waiting | “有一项操作需要你确认” | 是 |
| 需要审阅计划 | waiting | “计划已生成，等你审阅” | 是 |
| 任务完成 | success | “首页修改已完成” | 是 |
| 任务失败 | error | “任务失败了，点这里查看” | 是 |
| 没有活动任务 | idle | 不持续显示气泡 | 否 |

提醒附带会话名称和简短摘要。任务完成指 DSH 确认本轮执行结束，不把单次工具调用完成当作整个任务成功。真实事件语义见 [EVENTS.md](EVENTS.md)。

点击提醒的作用是定位会话。回答问题、批准操作、审阅计划仍在 DSH 中完成。

成功与失败使用短暂角色反馈，之后恢复当前工作状态；未读提醒保留到用户查看。等待状态持续到 DSH 确认等待结束，不能因为气泡超时或用户点击而变成工作中。

DSH 退出后，桌宠继续存在，表达“未连接”或休息状态。连接状态与五种任务状态分开建模，第一版可复用 idle 图片配合离线标识，无需增加第六套素材。

## 7. 多会话、未读和跳转

任务伙伴的会话列表与已读规则：

- 列表统计“有未读提醒的会话数量”，一个会话多条提醒只计 1，不向 DSH 或伴侣 Dock 写角标。
- 会话列表保留每个会话的当前状态、最新提醒和未读标记。
- 单一桌宠优先表现 waiting，其次短暂 error、success，再次 working，最后 idle。
- 相同优先级优先展示最近发生事件的会话，不按动画帧轮换。
- 气泡携带自己的目标会话，不随角色状态切换而改变点击目标。
- 点击角色：只有一个待关注会话时直接跳转；有多个时打开待关注列表供用户选择；没有待关注会话时打开当前工作会话或列表。
- 两种用途都从菜单栏打开设置；任务伙伴显示会话列表，纯桌宠不展示任务列表，历史未读保留到切回后查看。
- DSH 前台可见且具体会话加载成功、收到精确查看确认后，只清除捕获边界内的提醒。列表提供手动“标为已读”；按可见摘要自动已读仍留在历史清单待实施 / 验收，不作为本轮已实现能力。后台选中、只打开设置不全部清零，并发新增提醒按展示边界处理。

“未读”与“等待处理”分开：用户查看后可以清除未读，但只有 DSH 确认操作已处理，才解除 waiting。跳转失败不自动清除未读，并显示失败原因和重试入口。

## 8. 角色视觉与窗口体验

参考文件：`ds 娘.jpg`（本地资料，不随仓库发布）。图片只用于气质和视觉元素参考，不直接作为最终角色素材或动画规范。

可参考蓝白主色、Q 版比例、蓝色长发、明显呆毛、鲸鱼或海洋元素。简化蕾丝、裙边纹样、蝴蝶结数量及细碎发丝，重新设计服装和轮廓。正式形象不要求复制参考图的三视图。

当前准备同一角色五状态、每状态四帧的透明图集，保持统一缩放和脚底锚点；208 × 208 pt 角色画布，窗口 208 × 240 pt。用表情和姿态传递状态，待机长开眼后眨眼、工作打字、等待倾头、成功庆祝、失败担忧；系统减少动态效果时使用静态帧。实验室仍可比较 128–280 px 显示尺寸，生成细节漂移后续精修。

窗口支持拖动、屏幕边缘吸附和记住位置；重启后恢复。显示器拔插或分辨率改变时，保证角色回到可见区域。只有角色和气泡等可交互区域拦截鼠标，透明空白区域避免阻挡其他 App。

Always on Top 允许用户关闭；具体 Spaces 和全屏行为需要原型验证，不能保证覆盖所有全屏应用或系统窗口。动画应尊重系统“减少动态效果”设置。
