## 1. 确定的使用方式

用户仍只安装一个独立 macOS App，内置 DSH 插件。DSH 是任务入口，伴侣负责提醒和设置。伴侣在“应用程序”中正常打开，日常使用无需 Xcode。

| 行为 | Native | Desktop Pet |
| --- | --- | --- |
| 伴侣的 Dock 图标与角标 | 隐藏 | 隐藏 |
| 伴侣顶部菜单栏入口 | 保留 | 保留 |
| DSH 本体的 Dock 角标 | 显示未读会话数 | 显示相同未读会话数 |
| 系统任务通知 | 显示 | 不重复发送 |
| 桌宠与事件气泡 | 隐藏 | 显示 |
| 设置与会话列表 | 从菜单栏进入 | 从菜单栏或桌宠菜单进入 |

设置窗口关闭后仍继续运行。模式只决定提醒呈现，不改变未读记录和计数。取消此前“桌宠模式常驻 Dock”的建议。

## 2. 已读规则

角标表示尚未查看的提醒涉及多少个会话；同一会话多条提醒计 1，不表示等待批准的操作总数。

| 用户行为或状态 | 是否更新已读 |
| --- | --- |
| DSH 窗口在前台且可见，具体会话选中并加载成功 | 清除该会话当时已看到的提醒 |
| 通过通知、气泡或列表成功打开具体会话 | 保留现有规则：清除点击时捕获的提醒，不误清并发新提醒 |
| 伴侣会话列表在前台，提醒摘要实际出现在可见区域 | 清除对应会话展示时已有提醒 |
| 仅打开设置，或列表行尚未滚动到可见区域 | 不清空未读 |
| DSH 在后台、窗口隐藏/最小化，即使目标会话仍被选中 | 不作为已查看 |
| 关闭气泡、气泡超时、跳转失败或只唤起 App 而未确认具体会话 | 不标为已读 |
| 手动标为已读 | 保留现有能力 |

“看过”采用前台可见和实际展示作为判断依据，不声称能判断用户是否逐字阅读。一个会话被查看后，其他会话的未读继续保留。用户持续停留在会话中时，只有后续确认已经展示的新提醒才能继续标为已读。

已读与处理独立。问题、批准、计划审阅被看过后可以清除未读，但 waiting 仍持续到 DSH 确认处理完毕；不会自动回答、批准或审阅。

## 3. 技术修改范围

保留现有 CompanionCore 提醒记录为统一计数依据，避免 DSH client 与原生 App 各算一套未读。DSH 原生会话列表自身的完成提示不直接替代伴侣记录，其覆盖的事件和已读语义不同。

需要增加两条同步链路：

1. DSH client 观察前台可见、当前会话及加载状态，经 host 和现有鉴权本地通信反馈“已查看”。原生核心据此更新已读。
2. 原生核心把确认的未读数与更新版本传给 host，再由 DSH client 设置宿主 App 角标。

查看确认应携带来源实例、来源周期和所查看的事件边界或提醒 ID。实现时选择具体兼容格式，并验证旧插件不能把新增消息误当作会话跳转。过期来源、重复确认、较旧计数更新以及尚未展示的新提醒不得改变当前结果。

保留现有 eventId 去重、runId/等待身份、跳转目标确认、气泡固定目标和私有原子存储。模式切换、重新加载插件和断线不等于全部已读；重连以后从统一记录同步最新计数。退出/移除集成时的角标清理只针对本集成维护的显示，不清除真实未读记录，也不能覆盖未知来源的角标。

角色形象、复杂动画和 Live2D 探索继续独立进行，本方案不接入或替换美术素材。

## 4. DSH 本体角标的可行性验证

上一轮只读调查已核对本机 DSH 0.2.0-rc.2，Electron Framework 44.0.0，页面使用注册为 secure 的 dsh-app scheme。DSH 的专用 preload API 没有角标入口；Electron 的 Web Badging 实现提供另一条候选路径。

根据 [Electron 44.0.0 的 BadgeManager](https://github.com/electron/electron/blob/v44.0.0/shell/browser/badging/badge_manager.cc)，网页角标请求会进入宿主的 SetBadgeCount；[macOS 实现](https://github.com/electron/electron/blob/v44.0.0/shell/browser/browser_mac.mm) 设置本 App 的 Dock tile。**这是源码可行性证据，尚不是 DSH 实机成功证据。**

开发第一步先确认：

- DSH client 中 setAppBadge / clearAppBadge 是否存在、可调用，数字实际出现在 DSH 本体并可清除。
- 核对 DSH 自身通知/角标权限、前后台、重开和插件卸载行为；API 返回成功不能代替可见结果。通知权限可能影响角标显示，见 [Electron 文档](https://www.electronjs.org/docs/latest/api/dock/#docksetbadgetext-macos)。
- 验证没有与其他插件或 DSH 现有角标冲突；无法确认所有权时不盲目覆盖或清理。

默认方案不修改 DSH 安装包、重签 DSH、注入进程或关闭安全检查。若实机路径不可用，反馈具体限制，再确定替代方案；不自动改为伴侣显示角标、不伪装成 DSH。权限调整由用户决定，本轮不进行设置探针或修改系统权限。

## 5. 验收标准

- 两种模式下伴侣都不出现在 Dock，菜单栏入口始终可用；从 Applications 独立启动及重开设置正常。
- 两个会话有未读时，DSH 角标为 2；查看其中一个后为 1，查看另一个后清除。
- 同一会话多条提醒仍计 1；旧记录升级后保留，不通过清库实现迁移。
- 直接在 DSH 打开具体会话和从提醒跳转，都能同步正确已读；背景选中不清未读。
- 前台列表只清实际可见摘要对应的会话；滚动之外的提醒保留。设置打开和气泡关闭不全部清零。
- 查看确认之后到达、尚未展示的新提醒仍未读；旧确认、重发和乱序不覆盖新状态。
- 看过批准请求后角标可消失，但 waiting 与待处理入口仍存在。
- Native / Pet 切换保留相同未读数，历史提醒不重播。
- 断线、重连、插件更新/卸载以及能力/权限不可用时，行为明确，不出现虚假“已读”或“已成功设置角标”。
