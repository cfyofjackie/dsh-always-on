# 气泡外观、智能提醒与图标修改方案

日期：2026-10-04  
状态：五项代码已实现；自动检查通过，真实前台 / 全屏验收待解锁，见同一任务清单  
进度：[本轮任务清单](tasks/2026-10-04-气泡外观与智能提醒.md)

## 本轮要解决什么

设置里不仅能看角色动作，也能看气泡、选外观；用户正在 DSH 看结果时不重复打扰，进入 DSH 后提醒及时收起；全屏视频时桌宠默认隐藏。App 与菜单栏采用新版 DS 娘形象。

仍是一个 App 的 Native / Desktop Pet 两种模式。多只 DS 娘留到后续；另一会话正在进行的动画探索独立推进。

## 1. 气泡外观与测试

设置增加「气泡外观与测试」，与原有「动画测试」分开。

| 控件 | 行为 |
| --- | --- |
| 气泡外观 | 本轮提供「Q 版蓝白」和「简洁半透明」；默认蓝白，选择自动保存 |
| 气泡类型 | 完成、失败、提问、批准、计划审阅五类 |
| 设置内预览 | 直接看到所选样式与文案，改选后即时更新 |
| 在桌面预览 | 在 DS 娘旁边显示明确标注为测试的气泡 |
| 结束预览 | 收起测试气泡，恢复真实展示 |

外观选项只影响桌面伙伴气泡，原生通知继续使用系统样式。样式共用同一内容与交互，后续可增加款式；两款都要保留可读文字、指向角色的尾巴、整块点击和独立 ×。

设置内预览可在两种模式下查看；桌面预览只在桌面伙伴模式启用。测试持续到手动结束，不套用真实提醒的 5 秒 / 10 秒 / 直到打开规则。真实提醒进入时自动结束桌面测试，让真实提醒优先。

测试使用独立样例，不创建真实会话、不增加未读、不向 DSH 发送跳转或操作。点击测试气泡只结束测试并返回设置；测试开关重开 App 后关闭。真实气泡的点击与已读规则保持。

## 2. 当前会话前台静默与进入 DSH 后收起

「DSH 在前台」和「用户已看到某条提醒」分开判断。

| 用户正在做什么 | 提醒展示 | 已读变化 |
| --- | --- | --- |
| DSH 前台可见，产生提醒的会话正被选中、加载成功，相关内容已显示 | 不弹该会话气泡 / 系统任务通知，不播放完成或失败的提醒动作 | 只确认该会话已经展示的提醒 |
| DSH 前台，但提醒来自另一个会话 | 新事件正常提醒 | 保留对应未读 |
| DSH 后台、隐藏或最小化 | 正常提醒 | 保留未读 |
| 点击 DSH 使其进入前台 | 收起当前桌宠气泡和提醒动作，保留安静的角色状态 | 单纯唤起 App 不清未读 |
| 随后进入具体会话，相关内容已显示 | 该会话的现有提醒收起 | 只清已看到的记录，其他会话保留 |

前台静默覆盖完成、失败、提问、批准和计划审阅。看到 waiting 后仍需要用户在 DSH 回答、批准或审阅；查看不等于处理。工作 / 等待等真实状态继续记录，安静展示不伪造 idle 或成功。

进入 DSH 时收起的旧桌宠气泡不在离开 DSH 后重新弹一轮，提醒仍可从会话列表查看。此后来自其他会话的新事件继续正常提醒。Native 模式只移除已确认看过的对应系统提醒，不因为唤起 DSH 清掉其他会话的通知。

前台判断由 DSH 插件反馈实际会话与展示状态，结合原生前台 App 信息；不能仅根据窗口标题、缓存选中会话或 App 已启动判断。反馈必须有有效来源、时效与事件边界；旧确认不能清掉后来到达的新提醒。反馈缺失或不可信时保留提醒与未读，避免漏报。

这项接续 [通知与已读修改方案](通知与已读修改方案.md) 的前台查看反馈，使用同一份提醒存储。DSH 本体角标与伴侣 Dock 隐藏仍按 [原清单](tasks/2026-10-03-V0.1实现.md) 管理，本轮不额外扩张角标工作；前台静默不依赖角标先实现。

## 3. 全屏时桌宠默认隐藏

设置增加「全屏时显示桌宠」，默认关闭并保存。

- 默认情况下，桌宠和气泡不覆盖其他应用的全屏空间，包括问题 / 批准 / 计划审阅气泡；期间继续接收事件并保留未读。
- 退出全屏后恢复角色。旧气泡不逐条补弹，结果在会话列表保留；仍未处理的 waiting 恢复等待状态与待处理入口。
- 固定时长提醒不因隐藏重新计时；永久气泡也遵循退出全屏不补弹规则，记录保留。
- 主动打开「全屏时显示桌宠」后，恢复覆盖全屏的既有行为。手动桌面测试也遵循此设置。
- Native 模式仍由 macOS 专注模式决定系统通知呈现。本轮不承诺自动识别全屏并静音所有原生横幅，不修改用户专注模式。

系统全屏空间、浏览器视频全屏、窗口最大化分别验证；最大化窗口不直接当作全屏。多显示器按桌宠所在显示器判断，另一块屏幕全屏不应无条件隐藏所有桌面上的角色。优先调整窗口空间行为，不读取视频内容，不新增屏幕录制或辅助功能权限依赖。

## 4. App 图标

用新版 DS 娘的彩色头像或半身像，搭配简洁蓝白背景。放大脸部和头饰，适配 macOS App 图标轮廓，保证访达与小尺寸列表可辨认。

从当前已选形象制作独立图标资产，保留原图标备份与候选稿。图标先输出真实尺寸预览供用户回来查看，按已确认方向制作推荐稿；审美调整不阻塞其他功能测试。只更新 App 图标资源，不重新导出或替换角色动画。

## 5. 菜单栏图标

将当前铃铛替换为 DS 娘的单色头像轮廓：刘海、两侧头发和简化头饰。省去衣服、眼睛等小尺寸细节，与彩色 App 图标保持同一形象。

采用模板图像，由系统处理控件外观；验证浅色、深色、选中菜单与实际菜单栏尺寸。菜单入口、模式切换、设置和退出行为保持。本轮不增加独立的菜单栏未读计数或新的动画图标。

## 与另一会话的分工

用户已告知另一会话在独立页面继续动画探索。本轮使用既有角色，不调整动作或播放节奏。

| 工作 | 本轮边界 |
| --- | --- |
| 动画探索页面、图集、动作数据、生产角色资源、素材同步脚本 | 由另一会话负责，本轮不覆盖、不重新生成 |
| 角色播放器 `CharacterView.swift` 与已有动作预览 | 保留接口，本轮通过展示策略控制隐藏 / 恢复，不改播放器 |
| 设置、气泡、前台状态、提醒策略、窗口行为 | 本轮功能工作范围 |
| AppIcon 与新增菜单栏资源 | 本轮独立资产，来源使用当前形象的固定参考副本 |
| `Views.swift` / `Main.swift` / 工程资源引用 / 交接文档 | 可能共享；修改前重读最新内容，只做目标区域的小范围编辑 |

不重写整个共享文件，不恢复另一会话的改动，不停止其预览服务或进程；构建与截图记录实际素材版本。构建若遇到动画资源正在写入，保留现场，待资源稳定后重试，不通过回滚素材解决。新测试使用独立构建目录与随机偏好域。
